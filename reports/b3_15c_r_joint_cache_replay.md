# B3-15C-R：冻结策略重放与联合Cache收益归因

## 结论

使用1e-3正式Run的Update 75 `latest_checkpoint.pt`，对Training Seed 20001、20101、20201各执行300 Slot冻结随机策略Rollout；未运行PPO更新。每个Seed采用独立策略采样Seed 31515001、31515002、31515003。每个Episode在靠近Slot 40及200处选取一帧，且每帧至少两个节点实际改变Cache。

六帧的A分支均逐Slot复现了新冻结Rollout参考值：Task Utility、Cache Cost、UAV Cost和Return在`rtol=atol=1e-10`内一致，Matching映射一致。B和所有Cᵢ分支都通过正式Cache容量检查及Matching/KKT资源可行性检查；各分支从独立Cache状态开始，复用同一任务/车辆输入、UAV轨迹、Holding窗口和对应Slot的Matching随机状态。UAV轨迹固定，因此各状态的ΔUAV Cost为0。

同一Checkpoint、环境及策略采样Seed曾按相同协议再次重放，以获得紧凑结果摘要；这不是新增独立样本。两次执行选中的Slot和各帧更新节点数一致。冻结采集前后策略参数和训练计数器相同。

```text
REPLAY_BASELINE_EXACT = YES (6/6 states, per-slot)
VALID_JOINT_STATES = 6
JOINT_UPDATE_POSITIVE_FRACTION = 0/6 = 0%
JOINT_UPDATE_NEGATIVE_FRACTION = 6/6 = 100%
MEAN_JOINT_DELTA_RETURN = -0.3628921
NEGATIVE_NODE_MARGINAL_FRACTION = 19/20 = 95%
JOINT_ACTION_INTERACTION_EVIDENCE = LIMITED (2/6 non-additive residuals)
NINE_HEAD_OVER_UPDATE_SUPPORTED = SUPPORTED IN THESE SELECTED STATES
NODE_LEVEL_CREDIT_PROBLEM_SUPPORTED = INSUFFICIENT_EVIDENCE
```

该结果支持在所选窗口中，实际多节点联合更新经常没有抵消Cache重配置成本；不能把六帧视为全Training分布的无偏估计。现有证据不足以把负收益归因于节点级Credit Assignment：19个负边际更新节点的平均UPDATE组概率为0.3386，其中只有1个高于0.5；唯一正边际节点的UPDATE组概率为0.2624。策略没有在该小样本中持续以高于KEEP的概率偏好负边际节点。

**优先方向：** 后续先评估一个考虑总重配置成本的联合Cache更新门控，再决定是否调整节点级学习信号。当前不修改生产算法。

## 执行与证据边界

- Rollout为冻结策略随机采样，`policy.eval()`与`torch.no_grad()`生效；采样概率复用策略采样输出，没有额外前向推理。训练计数器和模型参数在采集前后相同。
- 每帧至少两个节点实际改变了Cache：节点变更数依次为5、3、4、4、2、2。B为决策前Cache；Cᵢ保持A的其他节点，只恢复该节点决策前配置。每个分支使用相同的实际Holding窗口及逐Slot UAV轨迹。
- Matching/KKT使用正式入口，未更改Reward、配置、候选规则或Checkpoint。A的逐Slot校验通过后才执行B及Cᵢ。
- 固定窗口内的6/6联合动作净收益为负，19/20单节点撤销边际为负。这支持在本次目标时段/状态中，多节点联合更新有过度发生的迹象；状态经过“靠近40/200且至少两个节点UPDATE”的条件筛选，不能据此估计所有训练状态的发生率。
- 撤销负边际节点能在对应窗口提高Return；实际联合动作没有比ALL_KEEP更好。该结果指向先研究联合更新门控/成本感知动作组合。它不证明共享Advantage是根因，也不构成训练分布上的长期结论。

本轮未修改正式源码、配置、Checkpoint或Run；未启动PPO训练、Validation或Test。临时采集脚本、内存轨迹及Numba临时缓存已在报告确认后清理。
