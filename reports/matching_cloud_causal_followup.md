## 结论

- 单任务无竞争时，Cloud 更优 28 项、最佳 Edge 更优 10 项、平局 0 项。Voluntary Cloud 并非全部由单任务效用优势解释。
- 原多任务状态下，62/62 个可行强制迁移改变了其他任务的效用；应把目标任务收益与共享 CPU/带宽及 Cloud CPU 重分配的外部效应分开看。
- Edge Gate 九 Slot 总任务效用差为 -8.75053238 (Legacy−Resource-aware)，Cloud 总量 38 vs 76。
- Matching 差距根因：A、B 单独迁移分别使系统任务效用下降 0.007509 和 0.005695；C 联合迁移提高 0.011184，并与已验证 DP 映射完全一致。当前 Transfer-Exchange 候选生成只含单任务 transfer 与两任务互换目标的 direct exchange（task_allocation.py:551-600）；Task 13 不具备迁移至 Task 54 原节点 UAV_1 的合法路径，因此 C 是跨三个节点的联合重分配，不在该邻域内。算法在 best delta 不超过容差时停止（task_allocation.py:1240-1248），故不能先接受负增益 A/B 再到达 C；该固定 Slot 的差距有直接证据支持为局部候选邻域限制。
- 代码核对：`src/decision/task_allocation.py:551-600` 只枚举单任务 transfer 和两任务交换彼此原目标；`1240-1248` 在最佳候选增益不超过容差时停止。Task 13 不能合法迁至 Task 54 的原节点 UAV_1，所以联合 C 不属于已枚举邻域。
- 联合非加性：C 相对 A、B 单独增量之和多出 `+0.024388813`，说明该固定状态的联合资源响应不可由单动作增量相加得到。
- 单任务/逐项迁移结果均为受限反事实，不是全局最优结论；Exact 最优性结果仅沿用前一轮三个 10 任务 Slot 的已验证 DP。
