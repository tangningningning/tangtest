# 阶段3C-4：缓存新增覆盖与实际卸载收益脱节的原因诊断

## 结论摘要

Stage3C3 的预测覆盖结果可追溯到 seed 专属 Validation realization；使用其保存的 Slot99 基准状态和正式Stage3B配置，对 Slot100–119 逐Slot重放 Matching 后，A基准分支的40个Slot任务效用与3C2 JSONL逐项完全一致，B分支的四组5/20 Slot任务效用总和也复现3C3报告。预测场景和实际任务没有发现 Slot100 输入错位。

新增服务0/2确实创造了实际RSU1候选：20 Slot中seed30020有98个、seed30023有58个新增RSU1可行路径。但分别只有1个新增候选最终在RSU1执行，其余97/57个由Cloud执行；service2候选没有一个被选为RSU1。受约束KKT重分配的5个代表性任务均降低整个Slot任务效用。主要解释是覆盖指标表示“有一个可行缓存路径”，不表示路径速率或效用足够高；当前RSU1的10MHz链路与5GHz CPU通常不及Cloud的有效上行速率和分得的CPU，RSU1已有任务时还会发生CPU/带宽竞争。

没有在有限重求解中找到Transfer-Exchange遗漏的更高效用单任务迁移；这不能证明全局最优或排除多任务联合改派。没有依据要求修改Matching，也不足以据此决定启动新PPO训练。

## 3. Cloud与RSU1时延及有限KKT重求解

沿用原模型公式，没有改动`psi_c=11`。Cloud通信时延为 `psi_c·D/R_cloud`，计算时延为 `L/f_cloud`；Edge通信时延为 `D/[α_B·B·log2(1+P·g/N)]`，计算时延为 `L/(α_f·f_node)`。配置中Cloud上行合同为200Mbps/任务，故在当前公式下对应18.18Mbps的等效通信速率；RSU1带宽为10MHz、CPU为5GHz。RSU1新增路径的全带宽实际速率在20 Slot范围为seed30020的0.127–10.887Mbps（中位0.535），seed30023的0.145–10.617Mbps（中位0.416）。Cloud有限池为60GHz；这些槽的Cloud CPU池使用满额，示例任务实际分配约4.8–7.5GHz。

选择规则为：每seed、服务0/2各取窗口内RSU1全带宽路径速率最高且当前Matching选Cloud的任务，再加入seed30020 Slot113一例（RSU1已有任务）检查节点竞争。对任务单独施加RSU1约束后，用完整`evaluate_matching_candidate`重算Cloud与Edge受影响任务组的KKT，比较整个Slot的Q。所有解均资源可行；Cloud仍用满60GHz。结果如下：

前四个案例当时RSU1没有Matching任务，受约束任务独占RSU1资源；即使将Cloud释放的CPU重新分给其余Cloud任务，整个Slot Q仍下降。最后一例同时覆盖了RSU1节点竞争：task46加入后与task51共享5GHz/10MHz，task51总时延也从4.500秒升至12.730秒、效用从0.861375降至0.585694。受约束评估会重新分配整个Cloud池和RSU1组，不是把原CPU分配冻结后只替换一个任务。

本轮有限重求解没有发现单任务迁移优于当前Matching。对测试任务而言，Cloud的实际联合任务效用更高；这不等于已证明所有任务/所有联合改派都如此。

## 4. A–D原因判断

- **A：Cloud当前具有更高联合任务效用——在5个受约束案例中得到支持。** 包括最强服务2链路案例，Cloud通信与计算合计仍短于RSU1；全Slot Q在完整KKT重分配后也均下降。
- **B：RSU1链路或资源竞争劣势——得到支持。** 多数候选全带宽速率低于Cloud公式的18.18Mbps等效速率。RSU1现有任务时，CPU/带宽拆分会让新增和存量Edge任务同时变慢。RSU1容量充足或Cache合法并不意味着链路效用高。
- **C：Transfer-Exchange局部最优遗漏更优分配——本次未发现证据。** 当前候选池保留Cloud及所有合法Edge目标，Matching停止于无改善；5个约束重算均未增益。没有做全局穷举或多任务联盟搜索，故不能排除未测的联合分配，也不能宣称全局最优。
- **D：预测覆盖变好，但实际需求/链路与预测不符——“需求缺失”不支持；“预测误差主导”也未证实。** 实际服务0/2需求存在，且Slot100十个任务的实际RSU1速率与同seed、horizon0预测中位数接近。更直接的解释是覆盖率只把路径可行性作为二元条件，不反映速率大小、Cloud/Edge计算资源份额、联合效用或竞争。Slot105–119超出Slot100的5步预测horizon，不用Slot100预测对它们作预测误差归因。

## 5. 证据边界与结论

上述结论限于seed 30020、30023、Cache候选#160及Slot100–119。有限约束重求解复现了现有模型，未修改Cloud参数、Matching/KKT、Reward、PPO或配置，也未运行训练、Validation或Test。预测覆盖的改善本身真实，但它表示增加“缓存且链路可行”的机会；本实验中大多数机会仍由Cloud取得，主要由速率和计算资源的效用比较解释。候选删除服务7/8/9还会改变存量任务的Edge选择，因此净结果不是只由新增服务任务决定。
