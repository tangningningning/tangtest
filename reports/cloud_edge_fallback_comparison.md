## 问题回答

1. Task Utility：四个状态差值合计 +6.27452182，每状态见上表。
2. Edge→Cloud 26 个任务，Cloud→Edge 0 个；另有 4 个 RSU→UAV 的 Edge 内迁移。共 30 个任务改变了具体执行节点，逐任务变化见 CSV。
3. 通信时延下降 28 个任务、上升 6 个；计算时延下降 27 个、上升 0 个。
4. 本样本 Edge 任务数从 34 降到 8；平均每个 Edge 任务获得的 CPU 从 2.441176 GHz 增到 5 GHz、带宽从 6.764706 MHz 增到 10 MHz。逐节点 KKT 分配和通信/计算时延均在表和 CSV 中，支持本样本 Edge 资源竞争减轻。
5. Cache UPDATE 后时延：四个样本点在当前 Slot 均没有 Cache 配置变化，不能直接确认新规则缓解 UPDATE 后时延恶化。
6. Cloud 任务占比（按任务数加权）：Legacy 48.48%、Resource-aware 87.88%。本次 Cloud 数量净增 26 个，均来自原 Edge 执行任务，其中 26 个仍有 Cache 命中。
7. 固定 Cloud 合同在本样本表现出很强替代性，可能压低 Cache/UAV 自适应的边际价值；但本次没有改变 Cloud 物理参数或比较长期策略回报，所以“压制自适应收益”的因果结论仍未确认。Stage 1 标定依据不足的结论仍成立。
