# 分层 PPO 收敛质量与策略自适应性分析

## 范围与口径

本报告只读取四个正式训练目录的最新 `episode_metrics.jsonl`、`update_metrics.jsonl`、`run_manifest.json`、`run_summary.json`，每组均为 300 Episodes、75 次 PPO 更新。确定性 Validation 只存在于 `1e-4` 与 `1e-3`：各有环境 seed 30001–30030、每个环境 300 Slot；未发现 `5e-4` 或 `5e-3` 的对应确定性 Validation。未读取 Test seeds 40001–40100。

训练 Episode 使用不同环境 realization，而且策略在训练中持续更新。因此，相邻 Episode Return 的变化既包含环境差异，也包含策略变化；它不能单独证明参数震荡或收敛。训练动作日志来自采样策略，不能与最终确定性 Validation 的 Argmax 选择混作同一种动作频率。现有数据没有历史 Checkpoint 在相同 Validation 环境下的配对评估，所以不能仅凭训练 Return 宣称严格收敛或策略最优。

- `SUPPORTED`：`5e-4` 与 `1e-3` 在后期进入较高的训练 Return 区域，其中 `5e-4` 的后100轮波动更小。
- `SUPPORTED`：`5e-3` 最后60轮出现持续的分段均值回落；`1e-4` 的后100轮 Return 离散度很大。
- `INSUFFICIENT_EVIDENCE`：四个策略是否已严格收敛。没有相同环境上的历史 Checkpoint 曲线或统一的跨 Checkpoint Validation，不能排除环境 realization 差异，也不能确认最终策略的收益稳定性。

所有 Manifest 的 Macro/Micro target KL 分别为 0.1 与 0.02。下表汇总 75 个更新的 PPO 指标；“尾20”是最后20次更新的 KL 均值。

`5e-3` 的最大 Macro KL 与 Clip Fraction 出现在第1次更新（0.4354、0.4748），Termination ratio KL/Clip Fraction 同次达到 0.2168/0.5108；前两次更新记录了 Macro early stop。之后没有延续成尾段异常：最后20次更新的 Macro KL 均值为 0.0068、P95 为 0.0150。四组 Micro KL 最大值均低于 0.02，Micro early stop 均为 0/75。

**优化稳定性判断：**

- `SUPPORTED`：`5e-3` 开始阶段发生过显著的 Macro 更新超调，并触发两次 early stop。
- `NOT_SUPPORTED`：现有更新记录不支持“持续性 PPO 数值失稳”；后三组无 Macro early stop，`5e-3` 的异常也没有延续到末段。
- 这只说明优化更新记录没有显示持续失稳，不说明策略已达到最优或不再变化。

## 4. Cache 策略自适应性

训练统计严格区分：`keep_rate` 是被选为 KEEP 的候选动作比例；`actual_cache_update_rate` 是 Cache 配置实际发生改变的宏决策比例。每一行依次列出 Episode 1–100、101–200、201–300。

| 学习率 | KEEP 候选动作比例 | 平均 KEEP 概率 | Cache 候选熵 | 每段实际 Cache 重配置数 |
|---|---|---|---|---|
| 1e-4 | 50.5 / 50.0 / 56.0% | 0.502 / 0.502 / 0.562 | 3.609 / 3.602 / 3.207 | 7,590 / 9,835 / 9,940 |
| 5e-4 | 64.6 / 80.3 / 89.1% | 0.635 / 0.802 / 0.887 | 2.698 / 1.348 / 0.675 | 6,341 / 4,905 / 2,768 |
| 1e-3 | 70.9 / 80.1 / 85.8% | 0.704 / 0.799 / 0.860 | 2.180 / 1.305 / 0.816 | 4,845 / 2,833 / 1,499 |
| 5e-3 | 72.2 / 74.9 / 90.4% | 0.717 / 0.754 / 0.901 | 1.980 / 1.509 / 0.550 | 4,736 / 3,753 / 1,863 |

训练的218,513个宏决策中，四组的非KEEP候选选择数都与实际 Cache 配置变更数相等（60,908次总计）；这些日志没有显示选了 UPDATE 却未发生配置变化。201–300段的 KEEP 候选比例分别为56.0%、89.1%、85.8%、90.4%。同段 candidate-0（KEEP）概率在同一 Episode 内的标准差均值分别为0.032、0.125、0.169、0.137，说明候选概率会变化；尤其后3组概率分布熵下降、KEEP概率升高，但这本身不能判断更新内容是否跟随服务流行度改变。

确定性 Validation 中：

- `1e-4`：9,000个宏决策有8,970次KEEP（99.67%）；平均 `p_keep=0.6402`，范围0.4238–0.6571。每个环境在零基Slot 0发生一次实际配置变化，30个环境共30次。
- `1e-3`：1,800个宏决策有1,680次KEEP（93.33%）；平均 `p_keep=0.8956`，范围0.0012–0.9635。每个环境在零基Slot 0、5、10、15各发生一次配置变化，30个环境共120次。概率在单环境内明显变化，但大多数宏决策选择KEEP。
- 两组验证中，实际重配置次数都与所选 UPDATE 次数一致；因此 KEEP 不能解释为缓存失效，也不能把实际配置变化次数等同于缓存命中/失效次数。

**Cache 判断：**

- `SUPPORTED`：多个学习率后期存在较高 KEEP 选择率；确定性Validation中1e-4与1e-3分别只在每环境1个、4个早期宏决策实际重配置，其余长期KEEP。
- `SUPPORTED`：KEEP/候选概率并非严格常数；训练概率标准差、1e-3验证中的 `p_keep` 范围都显示其随宏决策输入而变化。
- `INSUFFICIENT_EVIDENCE`：Cache 策略是否按服务流行度变化选择合适配置。现有汇总没有把流行度变化、具体配置差异和后续缓存结果按状态逐一对应，不能据此评价配置收益。

## 6. 确定性 Argmax 对动作集中的影响

检查范围限于 `src/ppo_simple/policy.py`、`src/ppo_simple/rollout.py` 的必要选择路径：

- `policy.py:595-620`：确定性 Holding 用 `argmax(logits)`；动作索引0为CONTINUE、1为TERMINATE，平局选索引0。
- `rollout.py:961-1008`：未到达最大Holding时才查询Termination；达到5 Slot上限时直接强制结束。因此若每个elapsed的Term概率都小于0.5，确定性策略会一路CONTINUE，再由上限得到5 Slot。
- `policy.py:122-157, 503-515`：Cache先按KEEP/UPDATE组概率质量Argmax；KEEP组选择候选0，UPDATE组内再以候选原始分数Argmax。Macro候选0被显式校验为合法KEEP（`policy.py:488-489`）。
- `policy.py:895-910`：UAV按STAY/MOVE组概率质量选择动作组，之后选择该组候选；STAY为组0、MOVE为组1。
- `rollout.py:1270-1307` 和 `1075-1084`：日志分别记录候选0概率状态标准差、候选熵、KEEP/UPDATE候选动作及实际配置是否变化，可用于区分策略动作与实际重配置。

所以当某个组概率为0.51时，Argmax会在该决策始终选它，不要求概率接近1。Validation中的Cache协议诊断在60个环境汇总中没有Group规则违规、UPDATE组内Argmax违规或非有限概率；概率和最大误差为约7.2e-7。未发现能解释这些结果的明显实现错误。该检查不是对策略质量的验证。

## 7. 已确认问题与尚未证实的问题

**现有数据支持的观察：**

- 1e-4与1e-3的确定性Holding分别固定为1 Slot与5 Slot；均由概率稳定处在0.5阈值一侧解释，1e-3另有最大Holding强制结束。
- 四组训练的Cache KEEP率都随训练阶段上升，确定性1e-4和1e-3验证长期KEEP；Cache重配置数已与选择的UPDATE动作分开核对。
- 5e-4的训练采样动作强烈偏STAY；1e-3确定性验证中UAV1动作组与位置均固定。
- 1e-4两架UAV、1e-3 UAV0的MOVE组虽然集中，目标位置仍持续变化。
- 5e-3在最后60轮Return持续下滑；它的Macro更新异常集中在早期，没有显示持续到训练末段。

**现有数据不能证明：**

- 四个最终策略已在相同环境下严格收益收敛或哪组策略最优。
- 固定Holding、KEEP偏好或低MOVE率会导致收益损失；未做动作因果收益比较。
- Cache配置是否跟随服务流行度变化而产生收益；摘要没有状态到配置收益的逐次对应。
- 5e-4、5e-3最终确定性UAV联合动作及MOVE目标位置是否变化。
- 1e-3/UAV1的固定STAY是否在当前环境下错误；只能确认它是集中决策行为，不能推断动作价值。

## 8. 是否有必要修改算法

**当前证据不足以支持立即修改算法。** 已确认确定性动作集中，但多处集中能由现有Argmax阈值与最大Holding规则直接解释，且没有发现选择实现错误。1e-3/UAV1的组与位置完全固定，以及后期Cache KEEP偏好属于需要继续观察的策略现象；仅凭这些日志无法判断它们是坏策略或不适合环境的策略。

## 9. 下一步唯一优先建议

先对四个最终Checkpoint完成同设置、同一组Validation seed的统一Validation，补齐5e-4和5e-3，并保留确定性组概率、Cache实际配置变化Slot、UAV目标坐标/候选来源与联合动作统计。用配对环境比较Return和策略行为后，再决定是否需要算法变更。此建议是后续行动；本次没有启动任何Validation或额外仿真。

## 最终回答

- **当前算法是否已经实现收益层面的收敛？** 严格收敛为 `INSUFFICIENT_EVIDENCE`；训练指标支持5e-4与1e-3进入相对稳定的高Return区，但缺少相同环境的Checkpoint验证。
