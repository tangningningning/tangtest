# Stage3 Cache 更新率异常与净效用下降：定向根因诊断

## 范围与执行方式

本报告只使用已有 Update 16/24 Checkpoint、训练与 Validation 产物，并补做一项允许范围内的 seed `30001` 配对诊断重放。原有完整评价 JSON 只有逐 Slot 奖励/成本，没有逐 Macro Trigger 概率、候选条件分布和节点动作明细，因此不能仅靠它定位阈值行为。

本报告的 **Update 24** 指 `mappo_stage3_decoupled_controlled_evaluation` 训练运行生成的 Checkpoint，SHA-256 为 `41e979bf193e13cd4f20f272dae5dbb77b86936ce0e61db56345ccc82fa87650`；起点 Update 16 SHA-256 为 `ca819d60320b3c65a46c2eb8217ca6d9e18f5a4bda2799f1778988f3976e611f`。工作区另有一个来自 `mappo_stage3_candidate_learning_experiment` 的 Update 24（SHA-256 `e0461c0f8e882e4c3d611a062f4b4df6c748a39c2f1fc61cc03c92864724e765`）；它不是本文 52.84% 更新率和 `−33.6067` 净效用差对应的 Checkpoint，本文不混用该结果。

诊断使用同一份 300 Slot Validation 输入、既有环境与奖励合同、确定性“先选操作组，再选合法条件候选”解码；Update 16 与 Update 24 分别从新建的同 seed 场景运行。两次净效用均与原完整评价逐位一致（差值为 0），Checkpoint/Manifest 合同匹配。没有调用 `Trainer.update()`，没有枚举反事实分支，没有读取 Test。每次重放约 49–51 秒。逐决策记录保存在 `runs/research_mappo_stage3_decoupled_controlled_evaluation/trigger_diagnostic_seed30001.json`。

策略实现依据：[mappo_baseline.py](../src/ppo_simple/mappo_baseline.py) 的 `_sample_macro_action` 通过分离的 Trigger logits 选择 KEEP/UPDATE，并在 UPDATE 后用独立 Candidate conditional logits 选择合法候选；确定性模式是对操作组概率取 argmax，因此 `P(UPDATE)>0.5` 即 UPDATE。[Stage1C 旧概率摘要辅助函数](../../adaptive_cache_mec-mappo-baseline-stage1/scripts/evaluation/evaluate_mappo_stage1c.py) 则从 `_macro_cache_node_logits` 的返回值同时计算 Trigger 与 Candidate 概率。解耦后该 helper 对 Candidate 概率使用了 Trigger logits，不能用来代表当前实际 Candidate 分布。本次逐 Macro 日志直接调用当前因子化接口，避免了该偏差。这个辅助函数问题只影响诊断摘要，不改变策略动作或系统回报。

## 1. Trigger 与更新率

下表分母为 1,350 次 Cache 节点决策（9 个节点 × 150 个 Macro 决策）。`P(UPDATE)>0.5` 与确定性解码规则一致；“变更”指实际缓存内容变化。

| 策略 | `P(UPDATE)` 均值 / 中位数 | 标准差 | `|P−0.5| ≤ 0.005` | `|P−0.5| ≤ 0.01` | 高于 0.5 的决策 | UPDATE / 实际变更 |
|---|---:|---:|---:|---:|---:|---:|
| Update 16 | 0.499586 / 0.498362 | 0.003873 | 71.93% | 99.63% | 314 / 1,350 | 314 / 314 |
| Update 24 | 0.500492 / 0.500108 | 0.005373 | 52.67% | 99.48% | 696 / 1,350 | 696 / 696 |

两个 Checkpoint 几乎所有节点决策都落在 `0.5 ± 0.01`。确定性阈值因此会放大很小的概率或状态分布变化：在 seed `30001` 中，平均 `P(UPDATE)` 只移动约 `+0.000906`，高于 0.5 的节点决策却增加 382 次；全部 2,700 个策略—节点记录的动作都符合 `P(UPDATE)>0.5` 判据，且所有 UPDATE 都是真实缓存变更，没有“UPDATE 标签多、内容没变”的计数假象。

变更集中在少数节点上。下表为各节点 150 次决策中的 UPDATE 次数，括号为该策略跨其自身轨迹的平均 `P(UPDATE)`：

| 节点 | Update 16 | Update 24 |
|---|---:|---:|
| SV 53 | 1（0.49837） | 1（0.49734） |
| SV 37 | 9（0.49977） | 150（0.50386） |
| SV 48 | 0（0.49860） | 92（0.50125） |
| SV 8 | 1（0.49829） | 1（0.49836） |
| SV 20 | 1（0.49842） | 150（0.50184） |
| RSU 0 | 1（0.49755） | 1（0.49516） |
| RSU 1 | 150（0.50335） | 150（0.50743） |
| UAV 0 | 150（0.50742） | 150（0.50738） |
| UAV 1 | 1（0.49451） | 1（0.49181） |

因此增加的决策主要是 SV 37、SV 20 和 SV 48 在 Update 24 的轨迹上转为高于阈值。Update 16 与 Update 24 首个 Macro 决策的九个操作组选择相同；首个状态上没有 Trigger 翻转。首个动作以后，缓存状态及环境状态随各自策略分叉，所以全 Episode 的节点均值不能解释为“同一状态下权重漂移”。本证据支持阈值放大效应，但无法把触发概率变化进一步分成参数更新影响与策略路径改变造成的状态访问分布影响。

按连续 30 个 Macro 决策分段，UPDATE 次数分别为 Update 16：`66, 65, 63, 60, 60`；Update 24：`153, 150, 121, 125, 147`。各段均出现较多接近阈值的状态，没有证据表明升高只发生在 Episode 某一短时段。

## 2. Candidate 条件选择与价值证据

在当前正确的独立 Candidate conditional 分布上，seed `30001` 的全决策归一化熵均值为 Update 16 `0.999920`、Update 24 `0.999885`（1 表示均匀分布）；平均最大候选概率分别为 `0.06832`、`0.06867`。按节点类型拆开，10 个候选的最大概率约 `0.103–0.104`，56 个候选约 `0.0186–0.0187`，34 个候选约 `0.0302–0.0305`，都只略高于均匀基线。故确定性 Candidate argmax 虽选中概率最大的候选，差别通常很小；分布本身没有明显集中到高价值少数候选。

既有 8 个固定诊断状态、7,079 个候选对的比较同样是混合结果：Update 16→24 的 Actor pairwise 排序准确率由 `0.52364` 降至 `0.50779`，最佳候选概率 `0.04140→0.04125`；条件贪心候选的有限期 ΔQ regret `0.27075→0.23991` 有改善，但条件期望 ΔQ `−0.20609→−0.20600` 基本不变。这不构成稳定的排序改善。

seed `30001` 首个 Macro 决策还有两个可复用的 Update 16 冻结 ΔQ 标签状态：

| 节点 | 合法候选数 | best 候选 ΔQ | Update 16 所选 | Update 24 所选 | 选中候选 regret（相对 U16 标签） |
|---|---:|---:|---:|---:|---:|
| RSU 1 | 56 | index 6：`+0.066658` | index 38：`−0.111002` | index 38：`−0.111002` | 两者均 `0.177660` |
| UAV 0 | 34 | index 2：`+0.031381` | index 33：`−0.516174` | index 19 | U16 为 `0.547555`；U24 无对应已保存标签 |

这支持“至少部分状态的实际候选低于同一状态的候选集合最佳值”，其中 RSU 1 的差距在两个策略间保持；不能把它外推为全 Episode 候选收益。标签定义为两 Slot 有限期 Macro SMDP 回报加冻结 Update 16 Critic bootstrap，是条件化价值估计，不是长期最优价值，也不是 Update 24 全 Episode Oracle。

Validation JSON 中的 Stage3 ΔQ 价值头摘要在三个 seed 各有 196 个候选标签，候选对排序准确率为 `0.679–0.723`，符号准确率 `0.819–0.833`；但其 Trigger 准确率为 `0/8`，真实正 best-ΔQ 为 8 个、价值头预测正例为 0。这里的 `trigger_accuracy` 是 **ΔQ 价值头**对 `max ΔQ > 0.01` 的判断，不是 Actor 的 `P(UPDATE)` 或操作动作准确率。它说明辅助价值估计与触发目标之间存在需要关注的不一致，不能单独证明 Actor 为什么选 UPDATE。

## 3. 净效用归因

沿用三个冻结 Validation Episode 的既有完整评价。逐场景 Update 24−Update 16 的变化如下（净效用=任务效用−Cache 成本−UAV 成本）：

| Seed | 实际变更数 U16→U24 | 任务效用差 | Cache 成本差 | UAV 成本差 | 净效用差 |
|---:|---:|---:|---:|---:|---:|
| 30001 | 314→696 | −0.8983 | +29.2100 | 0 | −30.1083 |
| 30002 | 316→722 | +0.5587 | +32.3217 | 0 | −31.7631 |
| 30003 | 332→722 | −8.1466 | +30.8023 | 0 | −38.9489 |
| **均值** | **320.67→713.33** | **−2.8287** | **+30.7780** | **0** | **−33.6067** |

平均额外 Cache 成本的核算量约为净效用下降的 91.6%；这是净效用分解的算术占比，不是单独 Cache 更新的因果效应。Cache 变更率三场景平均从约 `23.75%` 升至 `52.84%`，操作次数约 `2.22×`；每次操作的平均成本并非恒定，因此不能把成本差简单当作操作次数的线性倍数。

用三场景平均总 Cache 成本除以平均实际变更数，Update 16 每次实际变更的平均成本为 `0.115207`，Update 24 为 `0.094936`，约下降 `17.60%`；与此同时平均实际变更数增加 `392.67` 次，平均总 Cache 成本增加 `30.7780`。因此总成本升高来自显著增加的变更量及变更节点构成，而非单次变更成本整体变贵。该比值只是不同节点、不同候选成本的汇总均值，不代表存在统一的单次固定费率。

seed `30001` 的 5 个 30-Macro 区间里，U16/U24 的任务效用总量依次为 `780.225/780.074`、`787.438/787.413`、`795.214/794.576`、`797.252/797.123`、`781.309/781.353`，而 Cache 成本分别从 `7.581, 7.512, 7.241, 6.943, 6.943` 增至 `14.713, 14.346, 10.668, 11.273, 14.431`。该单场景诊断中，额外配置成本没有伴随可见的任务效用总量提升。三场景任务效用差并不一致（一个正、两个负），不能断言频繁更新在所有场景都降低任务效用，也不能把 Episode 差值分配给某一个动作。

两个策略 UAV 实际移动均为 0，UAV 移动成本为 0；Cache 与 UAV 动作合法，奖励合同最大误差为 0，数值异常和约束违规均为 0。因而没有证据指向非法动作、无效 UPDATE 计数、UAV 成本或奖励核算错误。当前净效用退化的直接账目来源是 Cache 成本上升；候选质量和任务效用是否由此受损仍不能做动作级因果归因。

## 根因判定与建议

- `TRIGGER_BOUNDARY_EFFECT_SUPPORTED = YES`：操作组 argmax 就是 0.5 阈值，99.5% 以上状态距阈值不超过 0.01；Update 24 在本场景增加了 382 个 `P>0.5` 决策，并全部成为有效缓存变更。它是更新率跃升的直接放大机制，但参数漂移与状态访问变化的份额未分开。
- `CANDIDATE_VALUE_MISMATCH_SUPPORTED = YES`：两个首状态中 Update 16 选中候选均低于已保存冻结 best-ΔQ；RSU 1 的 Update 24 仍选同一低值候选；固定诊断排序只有约随机水平且整体混合。仅支持有限样本，不证明完整 Episode 贡献。
- `CACHE_COST_DOMINATES_REGRESSION = YES`：平均 Cache 成本增量 `30.7780` 是净下降 `33.6067` 的主要算术项；任务效用另下降 `2.8287`。
- `OTHER_CAUSE_IDENTIFIED = NO`：没有发现足以解释回报差的系统执行、动作合法性或奖励记账错误。Candidate 条件价值与实际收益的全轨迹偏差仍无法量化。
- `ROOT_CAUSE_CONFIDENCE = MEDIUM`：成本账目和阈值触发路径有直接观测；但只补录了 seed 30001 的逐决策概率，ΔQ 仅有少数冻结状态，且策略轨迹在第一步后分叉，不能得出全状态因果结论。

**唯一优先建议：先校准 Macro Trigger 的有效监督信号与决策边界。** 保持成本权重和确定性解码规则不变，核对每个有效真实标签的 `best-ΔQ` 符号如何作用于实际 Trigger log-odds，重点记录有效 Trigger 比较数、辅助梯度对 Trigger 参数的实际贡献，以及固定状态上的 `P(UPDATE)` margin/决策。当前实现已有基于 best-ΔQ 的 Trigger 排序项，但每次更新只有 8 个有效标签，Validation 中 Actor 概率几乎都压在 0.5 周围，ΔQ 价值头也在 8 个正例上全预测为非正。应先验证这条监督链是否能将低值状态从阈值另一侧分开；本报告没有修改阈值、损失系数或算法。

该建议对应的最小验证应复用固定状态和已有合法 ΔQ 标签，不重跑完整 Episode：逐状态列出真实 best-ΔQ、训练目标、Trigger log-odds、`P(UPDATE)`、辅助梯度方向及更新前后距离 0.5 的 margin；只有确认监督标签到实际 Trigger 参数的映射和方向后，才决定是否需要最小代码修复。候选有限期价值与长期真实收益的对应关系仍需另外验证，不能借这次 Trigger 诊断宣称已经解决。
