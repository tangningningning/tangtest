# Stage6 Holding 1–5 Slot 配对净收益诊断

## 范围与结论口径

本报告只使用正式 Training 池和四个现存 latest Checkpoint。每个状态从相同决策前 Cache、UAV 位置和 Training Episode 状态复制五个独立分支；五个分支的首个 Cache 动作固定为原策略同一随机种子回放出的动作。首段 Holding 到期后，Macro、Micro 均使用对应 Checkpoint 的冻结确定性策略。每个分支分别通过正式 collect_dual_timescale_episode 执行五个 Slot，逐槽调用 execute_configured_slot 的 Matching/KKT 流程；KKT 求解器调用数由各 Slot 返回的实际摘要计数，不将一次 Slot 调用误当成一次求解器迭代。

策略输入由 src/ppo_simple/rollout.py::_observation（约第 360–386 行）构造，使用当前 Cache/UAV、预测特征和时间信息；真实 step.actual_tasks 仅在约第 916 行传给 execute_configured_slot 结算当前 Slot。分支从决策点之后才执行五个真实 Training Slot，没有将未来真实任务提供给策略。Training 对齐入口为 src/ppo_simple/interface.py:236；完整 Episode 回放中用同一随机种子复现决策点，随机种子机制见 src/ppo_simple/evaluator.py:239。收集循环与 Holding/Termination 处理见 src/ppo_simple/rollout.py:561–1055。

累计 Return 定义为五槽实际系统效用之和：G = Σ(Task Utility − Cache Cost − UAV Movement Cost)，与正式 Slot reward 合同相同。Delta_G(h) = G(h) − G(1)。Movement Cost 由分支实际的确定性 Micro UAV 决策产生，允许随 Cache 状态自然变化。结果只描述四个挑选状态的五槽累计表现；窗口外更远期收益未测，不能据此判断全时域最优或总体统计规律。

- 所有分支首个 Cache 动作相同，因此首个 Cache 改变本身不构成 Holding 之间的对照差异；后续 Cache 动作和 UAV 位置允许按分支新状态自然响应。后续 Cache 重配置的收益与成本均包含在分支实际轨迹中。
- 四个 Checkpoint 表现差异与不同策略行为相伴，但本实验没有对学习率或策略参数做干预。它检验冻结策略在少量状态上的 Holding 经济结果，不能把结果归因于学习率的因果效应。

## Holding 边界与 Termination 机制判断

本反事实在首个 Macro frame 上强制 Holding=h：h<5 时在第 h 槽强制 Terminate；h=5 时由系统原有 max-holding 规则结束首帧。达到指定长度后，所有新 Macro 与 Micro 决策都使用同一 Checkpoint 的确定性策略。没有修改 Termination 网络、KL 机制、Macro Advantage、Reward 或环境参数。

五槽窗口只显示所选状态下边界长度与其他 Holding 的实现累计收益比较。若 H1 或 H5 在某个状态胜出，只能说明该策略在该状态的五槽窗口内有收益证据；窗口外的缓存收益、重新决策频率和累计 UAV 响应没有测量。

**是否需要进一步修改 Termination 学习机制：UNKNOWN。** 这些分支提供 Holding 的经济结果，但不能证明 Termination 梯度或学习目标存在偏差，也没有足够状态样本判断边界集中是否普遍损害收益。当前证据不足以支持算法修改或断言无需修改。若要下结论，最小下一步是在更多独立 Training 决策状态重复同一五槽配对，并保留状态内配对与冻结策略规则；本报告不扩展为大规模实验。
