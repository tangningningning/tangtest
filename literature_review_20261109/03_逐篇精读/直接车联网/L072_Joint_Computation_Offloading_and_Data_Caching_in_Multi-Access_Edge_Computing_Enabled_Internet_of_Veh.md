# L072 — Joint Computation Offloading and Data Caching in Multi-Access Edge Computing Enabled Internet of Vehicles

## 1. 基本信息与阅读范围

Liqing Liu, Xiaoming Yuan, Ning Zhang, Decheng Chen, Keping Yu, Amir Taherkordi；2023；IEEE Transactions on Vehicular Technology 72(11): 14939–14953；DOI 10.1109/TVT.2023.3285073；文本共 16 页（p16 为参考文献续页）。已通读 p1–p15 正文，核对式(1)–(53)、Algorithm 1、Fig.1–8、Table I–III 标题与说明；**Table II 参数表的具体数值未被文本提取，标未核**。

## 2. 背景、问题与作者思路

【作者表述】IoV 中车辆算力/存储受限，MBS 与 RSU 均可承载 MEC；峰时与非峰时的流量差异显著；边缘缓存可减少重复传输与重复计算，故联合"执行模式、传输路径、子信道分配、缓存与缓存更新"（p1–p2）。峰/非峰分别建模：非峰全部卸载、用 SAGA；峰时可在本地或卸载、用 DQN（p1、p7–p11）。

【阅读判断】所谓"两个时段两套模型"实质是同一目标在"是否允许本地执行"上的两个特例，不是两种时间尺度耦合。真正接近"快慢反馈"的设计是缓存更新被刻意做成**每个时隙末**进行，作者明确对比"一般工作在长期尺度更新缓存"（p4），但没有保持周期或切换代价的概念。

## 3. 系统模型与对象

N 辆车、若干 RSU、1 个 MBS（含 MEC 服务器，位于路口）、中心云；RSU 覆盖被 MBS 重叠、二者同频；K 个 OFDM 子信道、带宽 B；RSU–MBS 有回传，回传时延与数据量成正比（ζG_i，式 8）。请求 RE_i={C_i, X_i, G_i}：C_i 为单位数据 CPU 周期，X_i 是仅存于车的本地动态数据，G_i 是"仅存于 MEC 或云、不变的数据库数据"（p3）。因此缓存对象是**数据库数据/内容**，不是程序、镜像或服务实例；无实例化、无迁移、无状态同步。通信节点（MBS/RSU）、计算节点（MEC 服务器）、存储节点（MEC 缓存，容量 O）三者在模型中被区分，但同一 MEC 服务器兼任计算与存储。MEC 执行时延式(24)把全体卸载负载求和后除以 f_M，所有卸载车辆共享同一时延（隐式拥塞外部性，无排队论）。车辆移动只体现在距离与信道增益。

## 4. 优化问题：目标、变量、约束

非峰时 P1（式 31）：min 加权平均执行时延 MWD^idle；峰时 P2（式 41）：min MWD^busy，峰时目标含本地执行分支（式 35）。决策 V(t) 含 p_i（二值卸载）、φ_i（二值缓存）、ψ_i∈{0,1,−1} 缓存更新、ρ^{up/down}_{i,j,k}（路径+子信道二值）；连续量（功率、带宽）未作为决策，隐含在速率式。约束（式 32a–i / 42a–i）：二值域、Σ_{j=0}^{1}ρ_{i,j,k}=1、E≤B̂_i、ψ_i≥−φ_i（式 2）、Σφ_iG_i≤O（式 1）、更新后容量≤O（式 3）。能量因果式(30)(40)被替换为区间估计 E∈[E_min,E_max]（式 34、44），作者称 E_min→0 时与原问题等价（p8 末）。**无任务截止期约束**，时延只是目标。

## 5. 求解方法

非峰：Lyapunov 漂移加罚（式 45–48）把长期能量约束解耦为逐槽问题 P3，再用 SAGA（模拟退火+遗传，Step 1–5）求逐槽解，复杂度式(51)。峰时：DQN（状态 Pos/O/B，动作即全部决策，奖励取 −MWD^busy，式 49–50，Algorithm 1），复杂度式(52)–(53)写作 O(n_t n_m)。**不是精确 MIP**；SAGA 无最优性保证，Lyapunov 只给漂移上界，DQN 无收敛保证。p1 贡献 3 与 p14 结论称 SAGA/DQN"achieve imitation learning"，表述不准确（二者均非模仿学习）。

## 6. 仿真实验

参数见 Table II（数值未核）。结果以 Fig.3–8 给出：非峰约 5 次迭代收敛、峰时约 43 次收敛（p13–p14）；缓存相对无缓存的优势在非峰"很小"，在峰时约 250 ms（p14 原文数值）；信道数 K=4/8/16；车辆数在 110–140 区间讨论。基线：有/无缓存、不同 K、不同车辆数，**无同类算法对比**。指标：平均执行时延、能量约束满足。

## 7. 作者明确指出的局限

无专门局限节。p14 自陈："we define the rate between MEC server and cloud center is very high in the simulation… so it does not take a long time for the data cached in the cloud to be transmitted back… the average execution delay difference between cached and no caching is about 250 ms, which is not particularly large"。

## 8. 阅读者发现的潜在局限

(1) **路径唯一性未被约束**：式(32d)/(42e) 只对每个子信道 k 要求 Σ_{j=0}^{1}ρ_{i,j,k}=1，并未限制"整条路径只能选一条"；而式(10)/(22) 用 max{·} 把两条路径的时延相加，若同一车辆在不同子信道上分别选中 RSU 与 MBS，会重复计入（p6 式 10、p7 式 22）。(2) 式(11) 称"接收下行数据的能耗"，却用基站发射功率 p^{down} 乘时延，实为发射侧能耗（p6）。(3) 式(12)(24) 出现未定义的 V_i(t)（请求模型只定义 C_i、X_i、G_i），应为数据量（p5、p7）。(4) 缓存每时隙更新却无替换/取回开销，ψ 只受容量与 ψ≥−φ 约束（p4 式 2–3），等于替换免费。(5) 车辆移动无切换或关联更新建模，RSU 始终取"最近"（p3）。

## 9. 与三个研究点的关系

- **P1 配置保持/剩余时限/快慢反馈：部分。** 有明确"缓存管理在每个时隙内完成、区别于长期尺度"的设定（p4），但无保持周期、无剩余时限、无慢层决策；缓存与卸载在同一槽内同时确定，不构成两层结构。
- **P2 预测误差/迁移窗口/传输竞争：未涉及。** 有车辆移动与距离时变，但无位置预测、无预测误差、无迁移、无迁移窗口；传输竞争只表现为同频干扰（式 13、16、20）。
- **P3 业务构成/流量/信道/在线部署：部分。** 峰/非峰业务构成差异被显式建模（p7–p9），子信道竞争与干扰已覆盖，SAGA/DQN 可在线；但流量非平稳只用两个时段代表，无到达过程或统计模型。

## 10. 可复用证据与不能说的话

可复用：数据库数据缓存 G_i 与任务执行耦合的写法（式 8、17、21）；峰/非峰双模型；Lyapunov 把能量因果解耦的处理（式 45–48）；缓存更新变量 ψ 与容量约束(3)。不能说的话：不能说它研究服务实例迁移或镜像预部署（缓存对象是数据库数据）；不能说它考虑切换或关联更新；不能把"250 ms"当作通用收益（是作者自陈的特定设置结果）；不能把 SAGA/DQN 称为精确求解或模仿学习。
